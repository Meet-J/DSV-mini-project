## Relationships
Every relationship is many-to-one, filters flow from the dimension to the fact only, and none is bidirectional. A text key is used because the dimensions have 3 to 7 rows; surrogate integer keys would add no benefit at this size.

| from (many side) | to (one side) | cardinality | filter direction | active |
|---|---|---|---|---|
| FactCustomer[Contract] | DimContract[Contract] | many to one (*:1) | DimContract filters FactCustomer (single) | yes |
| FactCustomer[InternetService] | DimInternetService[InternetService] | many to one (*:1) | DimInternetService filters FactCustomer (single) | yes |
| FactCustomer[PaymentMethod] | DimPaymentMethod[PaymentMethod] | many to one (*:1) | DimPaymentMethod filters FactCustomer (single) | yes |
| FactCustomer[TenureGroup] | DimTenureGroup[TenureGroup] | many to one (*:1) | DimTenureGroup filters FactCustomer (single) | yes |
| FactCustomer[ChargeBand] | DimChargeBand[ChargeBand] | many to one (*:1) | DimChargeBand filters FactCustomer (single) | yes |
| FactCustomer[RiskCategory] | DimRiskCategory[RiskCategory] | many to one (*:1) | DimRiskCategory filters FactCustomer (single) | yes |

| FactCustomer[RetentionSegment] | DimRetentionSegment[RetentionSegment] | many to one (*:1) | DimRetentionSegment filters FactCustomer (single) | yes |

Set under Column tools > Sort by column. Without them Power BI sorts text alphabetically: ChargeBand would read 35-65, 65-95, <=35, >95 instead of <=35, 35-65, 65-95, >95, and RiskCategory would read High, Low, Medium instead of Low, Medium, High.

## Hide in Report view
- On FactCustomer, the eight key columns: `Contract`, `InternetService`, `PaymentMethod`, `TenureGroup`, `ChargeBand`, `RiskCategory`, `CustomerStatus`, `RetentionSegment`. Visuals use the dimension's column instead (that is what makes the dimension, not the fact, the filter source).
- On every dimension, the `...Order` columns, `ColorHex` and `Definition` (they are used by sorting and by `[Risk Color]`, not shown).
- `FactCustomer[ProbabilityBinStart]` (used only to sort and colour the histogram).

## Design decisions
- **Snapshot grain.** The data has no dates, so there is no date table and no time intelligence. 'Trend' views use tenure cohorts instead.
- **Yes/No attributes stay on the fact** (SeniorCitizen, Partner, add-ons, and so on). A two-row dimension adds a relationship but no analytical value.
- **Risk and revenue measures use active customers only**, defined once in `[Active Customers]` and `[Active Monthly Charges]` so no measure can forget the filter.
- **Measures live in an empty `_Measures` table**, created with Enter data, so they stay together and are not tied to a data table.
- **Measures, not calculated columns,** for everything that aggregates: they respond to slicers and cost no memory per row.
